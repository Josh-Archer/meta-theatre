# Roadster finish and Starship — November 13, 2026

This change refines the Roadster's paint, reflections and surface textures and
adds an opt-in Starship launch/orbit/landing exhibit. It is layered on the
combined asset branch at `f282a19` (PR #23); it does not replace that branch's
close-Earth overlay with the different base-cap implementation from PR #22.

## Roadster material revision

The comparison baseline is `exports/realism_20261111/space_roadster.glb`.
The current version is `exports/starship_20261113/space_roadster.glb`, also copied
to `exports/flybys/space_roadster.glb` and the app's runtime asset.

- Cherry-red base color in linear RGB changes from `(0.400, 0.003, 0.008)` to
  `(0.235, 0.006, 0.012)`. Metallic stays zero; roughness changes 0.26 → 0.32.
- Clearcoat weight changes 0.80 → 0.55 and coat roughness 0.19 → 0.24.
- Windshield and visor metallic changes 0.48 → 0; roughness 0.12 → 0.18. These
  remain opaque dark-tinted surfaces, with no transparency sorting added.
- Fine-grain and carbon normal XY components are multiplied by 0.20 and
  renormalized into the original-size PNGs. Baking this into pixels keeps the
  subdued relief independent of importer handling of `normalTexture.scale`.

All accessor definitions, indexed geometry bytes, meshes and node transforms
match the baseline exactly: 136,900 triangles, ten material primitives and
five 512-square images. The GLB is 4,543,696 bytes. The source is
`blender/space_roadster_finish_20261113.blend`, with editable components and
packed images; reproduction is `scripts/refine_roadster_finish.py`.

`renders/starship_20261113/roadster_before.png` and `roadster_after.png` reimport
both GLBs under identical Blender studio lighting. The revision has a deeper
red and broader, softer highlights. The broad hood/windshield reflections
remain visible in this studio setup; headset material acceptance is still open.
No shape or topology repair is claimed by this material pass.

## Starship assets and flight

[Starship documentation](../STARSHIP.md) records source files, dimensions,
interaction, animation limitations, exact costs and reproduction commands.
The four new files total 4,020,032 bytes after lossless cleanup (42.2% below
Blender's initial 6,954,412-byte export). The cleanup asserts unchanged indexed
retained vertex values and image bytes; no source detail is reduced.

The opt-in 116-second trajectory is evaluated in Kotlin. Five cached native
entities render ship, booster, pad and two instances of the same exhaust mesh.
No transparent particles, mesh collisions or per-frame asset uploads are added.
The unculled flight budget is 121,136 triangles and 12 material
submissions. This is additional cost while the exhibit is active, not a measured
FPS improvement. Hidden assets remain resident for replay until session teardown.

The full pose sequence is exported by the trajectory test and rendered in
Blender for `renders/starship_20261113/starship-flight.mp4`. Its 6× playback,
review camera and preview label distinguish it from Quest footage. The native
app keeps the viewer's camera fixed and lets the user look around normally.
